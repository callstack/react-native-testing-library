### Summary

`eventDiagnostics` warnings for the modern event system.

With `configure({ eventDiagnostics: true, eventSystem: 'modern' })`, modern `fireEvent` now warns when it calls no handler, as legacy `fireEvent` already did, so a test doesn't silently do nothing. Modern `userEvent.press()` / `longPress()` diagnostics are aligned with the same reasons. Off by default, no warnings with `eventDiagnostics: false`. Legacy messages and snapshots are unchanged.

Modern `fireEvent` (generic `fireEvent()`, `fireEvent.press`, `.changeText`, `.scroll`, `.layout`) warns only when no handler or callback ran and native state wasn't updated. Reason precedence: `display: none` > `pointerEvents` > disabled / non-editable > responder declined on purpose (no warning) > no handler.

- Dropped events (`getEmittingTarget()` returns `null`, diagnosed by the new `getDroppedEventReason()`):
  - touch/pointer event hidden by `display: none`: `Cannot fire the "touchStart" event on an element hidden by display: none.` plus a new `Hidden by:` section with the element that sets it;
  - touch/pointer event blocked by `pointerEvents` everywhere: `... blocked by pointerEvents.` with `Blocked by:`;
  - text editing event on a non-editable `TextInput`: `... on a non-editable TextInput.` (named `changeText` for `fireEvent.changeText`);
  - `change` on a disabled `Switch`: `... on a disabled element.`
- Dispatched events that call no handler: `No "onTouchStart" handler found on the element or its ancestors.` for bubbling events, `No "onLayout" handler found on the element.` for direct events (including custom `dispatch: 'direct'` events), shown on the emitting target. `onChangeText` called through `afterTargetHandler` counts as a handler call (`afterTargetHandler` may now return `true`, which `dispatchEvent()` counts).
- Pressability events (`press`, `pressIn`, `pressOut`, `longPress`): `display: none`, `pointerEvents`, disabled skipped targets, or `No "onPress" handler found on the element or its ancestors.`; when the responder has no matching callback: `No "onPress" handler found on the touch responder.` No warning when a responder declines the touch, or when a responder without Pressability (`PanResponder`) claims it.

Modern `userEvent.press()` / `longPress()`:

- New: `press() interaction did not call any event handlers. The element is hidden by display: none.` with `Hidden by:`.
- An element without handlers inside `pointerEvents="none"` now reports the `pointerEvents` warning instead of "The element and its ancestors have no handlers for this interaction."
- A responder without Pressability (`PanResponder`) claiming the touch no longer warns.

Internals:

- `src/events/modern/warnings.ts` (new): `warnAboutDroppedEvent`, `warnAboutUnhandledEvent`, `warnAboutUnhandledPressabilityEvent`.
- `src/events/modern/pressability.ts`: `getDisplayNoneBlocker()` (replaces `isHiddenByDisplayNone`), `findPressResponder()` (responder + skipped targets, shared by modern `fireEvent.press` and `userEvent`), `isPressabilityResponder()`.
- `src/events/shared/warnings.ts`: `EventWarning.displayNoneBlockers`, printed as `Hidden by:`.
- Docs: `config.mdx` `eventDiagnostics` section and the modern event system page.

Base branch: `next/event-system` (the diff against `origin/main` also contains the event-system commits already merged there).

### Test plan

- New `src/events/modern/__tests__/warnings.test.tsx`: dispatched (bubbling, direct, custom, hit-test moved, scroll/layout native state, unmounted), dropped (`display: none`, `pointerEvents`, non-editable `TextInput`, disabled `Switch`, `changeText`), `changeText`, press cases, and `eventDiagnostics: false`.
- `src/user-event/__tests__/event-diagnostics.test.tsx`: modern `press`/`longPress` inside `display: none`, `pointerEvents="none"` without handlers, `PanResponder` responder.
- `src/events/modern/__tests__/dispatch.test.tsx`: `afterTargetHandler` returning `true` counts as a handler call.
- `src/events/__tests__/fire-event.test.tsx`: modern scroll on a child with `eventDiagnostics: true` now expects the "No onScroll handler found on the element." warning.

Run locally:

- `yarn test`: 192 suites, 2608 tests, 535 snapshots passed (legacy and modern projects).
- `yarn typecheck`, `yarn lint`, `yarn format:check`: pass.

Known gaps:

- `fireEvent.press` on a `TextInput` without `onPress` warns that the touch responder has no `onPress` (a `TextInput` always claims the touch in modern), where legacy calls an ancestor's `onPress` or warns that no element handles it.
- `fireEvent.layout` and `fireEvent.scroll` on a `ScrollView` always update native state, so they never warn (same as legacy).
